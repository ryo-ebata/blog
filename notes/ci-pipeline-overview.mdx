このブログのCIはGitHub Actionsで構築しています。PRを作成すると7つのジョブが並列で実行され、コード品質・テスト・ビルド・パフォーマンス・セキュリティを自動チェックします。

## 全体構成

エントリーポイントは `entry-pull-request.yaml` で、`pull_request` イベント（opened / synchronize / reopened / ready_for_review）をトリガーに、各ジョブを `workflow_call` で呼び出す構成です。

```yaml title=".github/workflows/entry-pull-request.yaml"
on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
    branches: [develop, main]

jobs:
  code-quality:
    uses: ./.github/workflows/job-biome-check.yaml
  unit-test:
    uses: ./.github/workflows/job-unit-test.yaml
  e2e-test:
    uses: ./.github/workflows/job-e2e-test.yaml
  build-check:
    uses: ./.github/workflows/job-build-check.yaml
  build-storybook:
    uses: ./.github/workflows/job-build-storybook.yaml
  lighthouse:
    uses: ./.github/workflows/job-lighthouse.yaml
  zap-scan:
    uses: ./.github/workflows/job-zap-scan.yaml
```

すべてのジョブは依存関係なしで並列実行されます。各ジョブは Reusable Workflow として分離されているため、個別にメンテナンスしやすくなっています。

## 各ジョブの詳細

### 1. Code Quality Check（Biome）

| 項目         | 値                     |
| ------------ | ---------------------- |
| ファイル     | `job-biome-check.yaml` |
| タイムアウト | 5分                    |
| 実行コマンド | `pnpm run check`       |

BiomeによるLint・フォーマットチェックを実行します。

### 2. Unit Test（Vitest）

| 項目         | 値                                                          |
| ------------ | ----------------------------------------------------------- |
| ファイル     | `job-unit-test.yaml`                                        |
| タイムアウト | 10分                                                        |
| 実行コマンド | `pnpm run test:unit --run` / `pnpm run test:coverage --run` |

Vitestでユニットテストとカバレッジ計測を実行します。一部のテストでPlaywright（Chromium）のブラウザ環境が必要なため、テスト前にブラウザをインストールしています。

### 3. E2E Test（Playwright）

| 項目         | 値                                     |
| ------------ | -------------------------------------- |
| ファイル     | `job-e2e-test.yaml`                    |
| タイムアウト | 20分                                   |
| 実行コマンド | `pnpm run test:e2e --project=chromium` |

PlaywrightによるE2Eテストを実行します。テスト結果は `playwright-report/` としてArtifactにアップロードされ、7日間保持されます。

### 4. Build Check（Next.js）

| 項目         | 値                     |
| ------------ | ---------------------- |
| ファイル     | `job-build-check.yaml` |
| タイムアウト | 5分                    |
| 実行コマンド | `pnpm run build`       |

Next.jsのプロダクションビルドが成功するかを検証します。型エラーやビルドエラーの検出に使用しています。

### 5. Build Storybook

| 項目         | 値                         |
| ------------ | -------------------------- |
| ファイル     | `job-build-storybook.yaml` |
| タイムアウト | 5分                        |
| 実行コマンド | `pnpm run build-storybook` |

Storybookのビルドが成功するかを検証します。

### 6. Lighthouse

| 項目         | 値                                |
| ------------ | --------------------------------- |
| ファイル     | `job-lighthouse.yaml`             |
| タイムアウト | 10分                              |
| ツール       | `treosh/lighthouse-ci-action@v12` |

Lighthouse CIでパフォーマンス・アクセシビリティ・ベストプラクティス・SEOのスコアを計測します。結果はPRにコメントとして投稿され、HTMLレポートへのリンクも含まれます。

`.lighthouserc.json` でしきい値を設定しており、3回測定の結果で判定されます。

```json title=".lighthouserc.json"
{
  "ci": {
    "assert": {
      "assertions": {
        "categories:performance": ["warn", { "minScore": 0.8 }],
        "categories:accessibility": ["error", { "minScore": 0.9 }],
        "categories:best-practices": ["warn", { "minScore": 0.8 }],
        "categories:seo": ["warn", { "minScore": 0.8 }]
      }
    }
  }
}
```

アクセシビリティのみ `error`（0.9未満で失敗）、他は `warn`（0.8未満で警告）としています。

### 7. OWASP ZAP Baseline Scan

| 項目         | 値                                |
| ------------ | --------------------------------- |
| ファイル     | `job-zap-scan.yaml`               |
| タイムアウト | 15分                              |
| ツール       | `zaproxy/action-baseline@v0.15.0` |

OWASP ZAPによるセキュリティスキャンを実行します。Next.jsのプロダクションビルドを起動し、`http://localhost:3000` に対してBaseline Scanを実行します。

結果はPRコメントとしてアラートのサマリーが投稿され、HTMLレポートはArtifactとして14日間保持されます。

`.zap/rules.tsv` でアラートごとにアクション（IGNORE / WARN / FAIL）を制御できます。

```text title=".zap/rules.tsv"
# Actions: IGNORE, WARN, FAIL
10038	WARN	(Sub Resource Integrity Attribute Missing - BuyMeACoffee外部スクリプトのため対応不可)
```

BuyMeACoffeeの外部スクリプトはSRI属性を付与できないため、WARNに設定してCIを止めないようにしています。

## 共通設定

すべてのジョブは以下の環境で実行されます。

- **ランナー**: `ubuntu-latest`
- **Node.js**: v24
- **パッケージマネージャ**: pnpm（`--frozen-lockfile` で依存関係を固定）

## セキュリティヘッダー

CIとは直接関係ありませんが、ZAPスキャンで検出された脆弱性への対応として、`next.config.ts` に以下のセキュリティヘッダーを設定しています。

| ヘッダー                   | 値                                         | 目的                            |
| -------------------------- | ------------------------------------------ | ------------------------------- |
| Content-Security-Policy    | `default-src 'self'; ...`                  | XSS・データインジェクション防止 |
| X-Frame-Options            | `DENY`                                     | クリックジャッキング防止        |
| X-Content-Type-Options     | `nosniff`                                  | MIMEスニッフィング防止          |
| Permissions-Policy         | `camera=(), microphone=(), geolocation=()` | デバイスAPI制限                 |
| Referrer-Policy            | `strict-origin-when-cross-origin`          | リファラー制御                  |
| Cross-Origin-Opener-Policy | `same-origin`                              | Spectre脆弱性緩和               |

加えて `poweredByHeader: false` で `X-Powered-By` ヘッダーを無効化し、サーバー情報の漏洩を防いでいます。
